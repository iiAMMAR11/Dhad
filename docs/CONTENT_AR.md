# دليل المحتوى العربي

## صوت النظام

النص عملي، هادئ ومباشر. يشرح الحالة والإجراء التالي، ولا يحمّل المستخدم تفاصيل تقنية لا تساعده.

- استخدم أفعالًا واضحة: «حفظ»، «إعادة المحاولة»، «حذف المشروع».
- سمِّ الفعل الحساس بدقة بدل «موافق».
- اجعل العناوين قصيرة، والنص المساند سطرًا أو سطرين عند الإمكان.
- لا تستخدم اللغة الاحتفالية في كل نجاح؛ «تم الحفظ» يكفي.
- لا تلُم المستخدم. اشرح ما حدث وما يستطيع فعله الآن.

## الأفعال والحالات

| السياق | صياغة مفضلة | تجنب |
|---|---|---|
| حفظ جارٍ | جارٍ الحفظ… | انتظر |
| نجاح | تم حفظ التغييرات | رائع! نجحت العملية بنجاح |
| فشل قابل للمحاولة | تعذر الحفظ. تحقق من الاتصال ثم أعد المحاولة. | خطأ 503 |
| دون اتصال | تعمل دون اتصال. ستتم المزامنة عند عودة الشبكة. | Offline |
| صلاحية قراءة | لديك صلاحية عرض فقط. | ممنوع |
| حالة فارغة | لا توجد مشاريع بعد. أنشئ مشروعك الأول. | لا توجد بيانات |
| حذف | حذف المشروع | نعم / موافق |

رسالة الخطأ القريبة من حقل تبقى inline. نتيجة عملية عابرة تستخدم toast. فشل الحفظ أو المزامنة يبقى ظاهرًا حتى نجاح لاحق.

## العربية وRTL

- عيّن `lang="ar"` و`dir="rtl"` عند الجذر.
- اكتب DOM بترتيب القراءة والمعنى، ولا تقلبه بصريًا فقط.
- استخدم logical properties و`start/end` بدل `left/right` للتخطيط العام.
- لا تضغط line-height العربي؛ اختبر الحركات والهمزات واللام ألف والقص داخل الأزرار.
- لا تستخدم حجم 11px لمعلومة أساسية.
- افصل الرمز عن النص بمسافة ثابتة ولا تعتمد على ترتيب Unicode العشوائي.

## الجزر ثنائية الاتجاه

البريد والرابط واسم الملف والكود والتايم كود والمعرّف التقني جزر LTR داخل الصفحة العربية:

```html
<p>أرسل الملف إلى <bdi dir="ltr">team@example.com</bdi></p>
<code dir="ltr">INV-2026-0042</code>
<time class="dhad-timecode" dir="ltr">00:14:23:08</time>
```

وفي CSS:

```css
.technical-value {
  direction: ltr;
  unicode-bidi: isolate;
  font-variant-numeric: tabular-nums;
}
```

قواعد:

- استخدم `bdi` للقيم الديناميكية مجهولة الاتجاه.
- لا تضع الأقواس أو النقطتين داخل قيمة ديناميكية بلا عزل؛ قد تقفز العلامات إلى الطرف الخطأ.
- لا تقسّم URL على أحرف عشوائية تجعل نسخه غير صحيح.
- ثبّت سياسة الأرقام داخل السياق الواحد؛ لا تخلط 123 و١٢٣ في الجدول نفسه بلا سبب.
- استخدم monospace للقيمة التقنية فقط، لا لكل labels.

## الحقول والتحقق

- لكل حقل label حقيقي ظاهر أو متاح؛ placeholder مثال وليس تسمية.
- اربط help وerror عبر `aria-describedby`.
- اذكر الخطأ المحدد: «يجب أن يحتوي الاسم على 3 أحرف على الأقل».
- حافظ على القيمة التي كتبها المستخدم عند الفشل.
- لا تعتمد على حد أحمر وحده؛ أضف نصًا أو رمزًا له اسم متاح.

## الإيموجي داخل المحتوى

- استخدمها فقط إذا طلبها المستخدم أو كانت جزءًا من لغة المنتج.
- الإيموجي الزخرفية `aria-hidden="true"`، والإيموجي المعلوماتية تحتاج نصًا مكافئًا.
- زر الإيموجي المنفرد يملك `aria-label` يصف الفعل.
- لا تستبدل كلمة حالة مهمة برمز وحده.
- راجع [سياسة الإيموجي](EMOJI_AR.md) قبل إنشاء القاموس.

## اختبار النص

اختبر على الأقل:

- عنوان عربي طويل مع حركات.
- اسم مستخدم إنجليزي داخل جملة عربية.
- URL طويل، بريد، اسم ملف وتايم كود.
- قيمة فارغة، صفر، عدد كبير وتاريخ.
- رسالة خطأ من سطرين أو ثلاثة.
- تكبير 200% وعرض 320px.
- قراءة VoiceOver أو قارئ شاشة عربي للحالات المتغيرة.
