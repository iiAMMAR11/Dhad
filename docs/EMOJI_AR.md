# سياسة الإيموجي المتكيّفة

## القرار قبل الرمز

لا يفرض Dhad الإيموجي على كل واجهة. يقرر استخدامها بعد فحص أمرين:

1. هل طلبها المستخدم أو وصف بها النبرة المطلوبة؟
2. هل يملك المنتج المضيف لغة إيموجي أو أيقونات مستقرة يمكن احترامها؟

إذا كانت الإجابة «لا»، فلا تضف الإيموجي. الامتناع هنا تطبيق صحيح للنظام، لا نقصًا فيه.

## بناء قاموس خاص بالمنتج

عندما تكون الإيموجي مناسبة:

- اختر رمزًا واحدًا ثابت المعنى لكل مفهوم متكرر.
- استخرج المفاهيم من مجال المنتج الحقيقي، لا من أمثلة منتج آخر.
- التزم بدرجة تعبير واحدة: عملية وهادئة، أو ودية، أو تعليمية بحسب طلب المستخدم.
- تجنب الرموز التي تحمل معنى ثقافيًا ملتبسًا إذا كان النص يستطيع توضيح الفعل مباشرة.
- وثّق القاموس قرب توكنز المنتج أو مكوّناته، مثل `project`, `archive`, `warning`, `celebration`.

القاموس يتغير من منتج لآخر. على سبيل المثال، 🎬 قد يكون منطقيًا في منتج تصوير، لكنه ليس الرمز الافتراضي لمشروع أو مهمة في نظام مالي.

## عقد runtime القابل للعكس

يدعم `Dhad.configureSymbols` أربعة أوضاع: `inherit` و`emoji` و`icon` و`none`. لا يُفترض أن يدمّر أي انتقال محتوى المضيف:

- يعيد `inherit` المحتوى والسمات الأصلية بعد أي وضع سابق.
- تترك الخريطة الجزئية الرمز الأصلي لأي دور غير معرّف.
- يخفي `none` الرمز دون حذف مصدره.
- يقبل `icon` عقدة DOM أو دالة تعيد عقدة. وإذا كانت قيمة الأيقونة اسمًا نصيًا، فيلزم `renderIcon` لتحويله إلى عقدة فعلية.

```js
Dhad.configureSymbols({
  mode: "icon",
  map: {
    archive: { emoji: "🗃️", icon: "archive" }
  },
  renderIcon(name) {
    const template = document.querySelector(`#icon-${name}`);
    return template.content.firstElementChild;
  }
});
```

لا تستخدم SVG نصيًا غير موثوق ولا `innerHTML` لبناء الأيقونة. أعد عقدة DOM من مصدر محلي معلوم.

## الاتساق البصري

- لا تستخدم emoji وoutline icon وfilled icon ورسمًا مخصصًا بالتبادل للفعل نفسه.
- يمكن استخدام الإيموجي داخل المحتوى وأيقونات ثابتة للتحكم إذا كانت الحدود بين الدورين واضحة.
- لا تعتمد على محاذاة الإيموجي أو ألوانه الدقيقة كجزء من الشعار؛ عرضه يختلف بين Apple وGoogle وMicrosoft والمنصات الأخرى.
- اختبر السطر العربي، baseline، line-height والقص على الأنظمة المستهدفة.
- لا تضع صندوقًا ملونًا خلف كل إيموجي تلقائيًا. أضف الحاوية فقط إذا كان لها دور وظيفي مثل target تفاعلي واضح.

## الوصول

### إيموجي زخرفية

```html
<h2><span aria-hidden="true">📚</span> مكتبة الفريق</h2>
```

النص يقدّم المعنى، لذلك يُخفى الرمز عن قارئ الشاشة.

### إيموجي معلوماتية منفردة

```html
<span role="img" aria-label="تحذير">⚠️</span>
```

يفضل إضافة نص مرئي مثل «تحذير» عندما تكون الحالة مهمة، كي لا تعتمد المعلومة على الرمز وحده.

إذا استخدمت `data-dhad-symbol` مع runtime، يحافظ الرمز المنفرد ذو `role="img"` أو `aria-label` على اسمه المتاح، بينما يُخفى الرمز الموجود داخل زر أو رابط لأن اسم التحكم يجب أن يكون على المالك التفاعلي نفسه.

### زر يعتمد على إيموجي فقط

```html
<button class="dhad-icon-btn" type="button" aria-label="أرشفة المشروع">
  <span aria-hidden="true">🗃️</span>
</button>
```

يصف `aria-label` الفعل الناتج، لا اسم الرسم. يجب أن يبقى target بحجم 44×44 نقطة منطقية على الأقل، أو معيار المنصة إذا كان أكبر.

## اختبار ما قبل التسليم

- هل طلب المستخدم الإيموجي أو يدعمها نظام المنتج؟
- هل لكل رمز معنى واحد موثق؟
- هل نُقلت أي رموز من منتج آخر بلا علاقة بمجال المنتج؟
- هل توجد لغة بصرية واحدة لكل نوع من الأفعال؟
- هل كل emoji-only control يملك اسمًا متاحًا؟
- هل الرموز الزخرفية مخفية عن أدوات الوصول؟
- هل بقيت الحالة مفهومة عند إزالة اللون والرمز؟
- هل اختُبر العرض على نظامين على الأقل عندما تكون الإيموجي جزءًا متكررًا من الواجهة؟

في ملخص التسليم، اذكر قرار الإيموجي وقاموسها أو اذكر صراحة أن المنتج لا يستخدمها.
