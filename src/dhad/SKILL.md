# ضاد

ضاد تجعل أي عمل أو واجهة أو ملف أوضح وأسهل، وتهتم بالعربية وRTL من البداية. تتبع هوية المشروع ولا تفرض شكلًا واحدًا.

## طريقة العمل

1. افهم ما الذي يريده المستخدم، ولمن، وفي أي شكل ستكون النتيجة.
2. حافظ على هوية المشروع وخطه وألوانه وما يعمل فيه جيدًا.
3. حمّل فقط ما تحتاجه:
   - واجهة أو تجربة استخدام: [الأساس](references/foundation.md).
   - نص أو أرقام أو تاريخ عربي: [العربية والمنطقة](references/arabic.md).
   - موقع أو تطبيق أو عرض أو PDF أو صورة: [أنواع النتائج](references/outputs.md).
   - بحث أو محتوى أو خطوات استخدام متقدمة: [أفكار جاهزة](references/patterns.md).
   - مراجعة العمل قبل تسليمه: [الفحص](references/quality.md).
4. نفّذ أبسط حل يحقق الهدف، ثم جرّبه في النتيجة الحقيقية.

## ثوابت ضاد

- اختيار المستخدم وهوية المشروع أولًا.
- لا تفرض خطًا أو لونًا أو شكلًا أو أداة. الملفات المرفقة مجرد بداية اختيارية.
- ابدأ العربية من اليمين، واترك الرابط والبريد والكود والرقم الطويل في اتجاهه الصحيح.
- اترك مسافة داخلية مريحة بين النص وأي إطار أو حافة، بالعربية والإنجليزية.
- أعطِ كل سطر عربي ارتفاعًا يحمي التشكيل والهمزات، واختبر نصًا مشكّلًا قبل التسليم.
- اجعل الكلام ظاهرًا، والأزرار عاملة، والتركيز واضحًا، ومساحة اللمس 44px على الأقل.
- اختبر النص الطويل، والعربية مع الإنجليزية، والتكبير، والهاتف، والنتيجة النهائية مثل PDF أو الصورة.
- لا تستخدم لغة تقنية مع المستفيد إذا كانت عبارة بسيطة أو مثال يومي يشرح الفكرة.
- تبقى مراجع الدراسة خارج ملفات المهارة التشغيلية؛ مكان الشكر العام هو README وموقع الاستعراض فقط.

## التسليم

قل باختصار ماذا حسّنت، وماذا جرّبت، وما الذي يحتاج قرارًا من المستخدم. لا تشرح له بنية المهارة الداخلية.
