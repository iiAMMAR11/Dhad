# مواصفات Dhad

## 1. تعريف النظام

**Dhad** نظام واجهات عربي أصيل لتطبيقات الإنتاجية التي تُستخدم تحت ضغط حقيقي. هويته عملية وهادئة، ويتعمد تقليل الحمل الذهني بدل جذب الانتباه إلى نفسه.

بُني النظام من تحليل منتجات عربية فعلية واختبار أنماطها في الاستخدام، ويغطي الثيمين، قواعد الجوال، الحالات التفاعلية، رسائل الخطأ، المزامنة، والاستيراد والتصدير.

## 2. شخصية النظام

أربع صفات تلخصه:

| الصفة | ما تعنيه في الواجهة |
|---|---|
| احترافي | بيانات حقيقية، حالات واضحة، لا زينة بلا وظيفة |
| دقيق | أرقام ثابتة العرض، progress قابل للقياس، أسماء حالات صريحة |
| هادئ | أسطح منخفضة التباين، كثافة مدروسة، ألوان دلالية محجوزة |
| ميداني | أهداف لمس كبيرة، وصول سريع، دعم safe-area وإضاءة متغيرة |

المبدأ المركزي: **الأداة تختفي خلف المهمة**.

## 3. بنية النظام

### 3.1 Core

صالحة لكل مشروع:

- الألوان الدلالية.
- الخطوط والمقاسات.
- المسافات والـ radius.
- الأزرار والحقول.
- البطاقات والأسطح.
- أدوار الاختيار المحايدة المنفصلة عن النجاح.
- المال والقيم الرقمية المختلطة الاتجاه.
- حالات النجاح والخطأ والتحذير.
- focus، disabled، loading، saved، offline.
- toast وbottom sheet.
- responsive وreduced motion.

### 3.2 Patterns

تُستخدم عند الحاجة:

- topbar ثابت/لزج.
- page shell بعرض أقصى 1040px.
- sticky action bar أسفل topbar.
- cards/list/kanban كطرق عرض بديلة لنفس البيانات.
- tabs وsegmented radio وview toggle بعقود دلالية منفصلة.
- summary grids وledger rows وحقول مترابطة.
- compact data chart مع بديل نصي.
- checklist مع progress.
- empty state مع فعل واضح.
- decision dialog يتحول إلى bottom sheet على الجوال، مع task-form dialog منفصل للإدخال الطويل.
- محرر كتابة بعرض قراءة 660px.

### 3.3 Domain recipes

الوصفات اختيارية ولا تدخل Core. الوصفات الموثقة:

**إنتاج الفيديو:**

- Project / تصوير.
- Segment / مقطع.
- Shot / مشهد.
- Timecode / ملاحظة زمنية.
- Teleprompter / قارئ.
- FCPXML export.

**المصاريف المشتركة:**

- Expense / مصروف.
- Participant / مشارك مالي.
- Split / تقسيم.
- Balance / رصيد.
- Settlement / تسوية.
- Currency conversion / تحويل تقريبي.

هذه الطبقة قابلة للفصل. مشروع مالي يأخذ Core وPatterns ووصفة المصاريف المشتركة عند مطابقة تدفقه، ولا يأخذ أسماء أو أيقونات التصوير. راجع `references/shared-expenses.md` في مجلد المهارة ولا تنقل منطقها إلى منتج لا يحتاجه.

### 4.4 قواعد الاستعمال

- accent: الأفعال الأساسية، التركيز والتقدم العام. لا يستعمل كبديل تلقائي لكل حالة اختيار.
- success: نتيجة ناجحة أو اكتمال حقيقي فقط، لا يستخدم كزينة.
- danger: الحذف والخطأ فقط.
- warning: انتظار الحفظ أو حالة تحتاج انتباهًا دون فشل.
- timecode: الوقت والملاحظات الزمنية فقط.
- assistive: إجراء مساعد أو مشاركة، ولا ينافس الفعل الأساسي. الدور دلالي ولا يسمى باسم اللون.
- selection: الحالة المحددة في tabs وradio segments وselected rows وcheckboxes الاختيار. لا تستخدم accent أو success بديلًا عنها لمجرد أن المكوّن نشط.
- checkbox اختيار مشارك ليس success؛ checklist مكتملة يمكنها استعمال success.
- حالات كتابة/جاهز/تحرير خاصة بوصفة إنتاج المحتوى وتبقى تحت `recipe.production`، ولا تدخل Core العام.
- tint شفاف للحالة، واللون الصريح للنص أو النقطة؛ لا تملأ مساحات كبيرة بألوان الحالة.

## 5. الخطوط

### 5.1 العائلة

| العائلة | الدور | الأوزان |
|---|---|---|
| IBM Plex Sans Arabic | خط ضاد الوحيد لكل الأدوار — نص، واجهة، عناوين، هوية | 100، 200، 300، 400، 450، 500، 600، 700 |
| SF Mono / Menlo | timecode والقيم التقنية | ما يتوفر من النظام |

الأوزان الثمانية مضمّنة في `assets/starter/fonts/` برخصة OFL-1.1 وتعمل بلا اتصال ولا CDN. لا تُدخل عائلة عربية ثانية أبدًا — التمايز بين العنوان والفرعي والنص يأتي من الوزن والحجم واللون معًا وفق references/fonts.md: النص الجاري 450، عناصر الواجهة 500، العناوين 600–700، وما دون 400 لأحجام العرض الكبيرة فقط (≥28px). الترتيب:

```css
--dhad-font-body: "IBM Plex Sans Arabic",
  -apple-system, "BlinkMacSystemFont", "Geeza Pro", "Arabic UI Text",
  "Traditional Arabic", "Al Nile", "Helvetica Neue", Arial, sans-serif;

--dhad-font-display: "IBM Plex Sans Arabic", "Geeza Pro", Arial, sans-serif;
```

للويب ثبّت البديل الرسمي المفتوح عبر `npm install @ibm/plex-sans-arabic`، ثم استورد Sass من `@ibm/plex-sans-arabic/scss` أو استخدم أصول الويب الرسمية للحزمة. في Native لا يكفي استيراد npm: إمّا أن يدمج المنتج ملفات IBM ويسجّلها وفق OFL-1.1 مع إشعار الترخيص، أو يختار خط fallback عربيًا من المنصة وقت التشغيل.

Radius:

- 6px: عناصر داخلية صغيرة.
- 10px: زر وحقل.
- 14px: بطاقة أو toast.
- 18px: بطاقة مشروع أو سطح رئيسي.

- topbar: 52px قبل safe-area.
- minimum touch target: 44px.
- max page content: 1040px.
- project content: 920px في واجهات المشاريع.
- reading/writer width: 660px.

## 7. المكوّنات

### 7.1 الأزرار

| variant | الاستخدام |
|---|---|
| Primary | الفعل الرئيسي الوحيد في السياق |
| Success | إنهاء/اعتماد/تشغيل ناجح |
| Secondary | أفعال ثانوية فوق سطح واضح |
| Quiet | إلغاء أو فعل منخفض الأولوية بلا اقتران افتراضي بين زر ممتلئ وآخر محدد الإطار |
| Danger | حذف أو قرار لا يمكن تجاهله |
| Assistive | مشاركة أو فعل مساعد خاص |
| Timecode | التحكم بالزمن فقط |
| Icon | فعل معروف، مع `aria-label` إلزامي |

الحالات: default، hover، active، focus-visible، disabled وloading. لا يغيّر الزر موضعه أو حجمه عند hover، ويبقى هدف اللمس 44px على الأقل.

### 7.2 الحقول

- input/select/textarea: سطح دلالي واضح، حد 1px، radius 10px.
- focus: border دلالي + ring شفاف 3px.
- اتجاه الحقل RTL افتراضيًا.
- البريد، الرابط، رقم الملف والتايم كود يمكن تحويلها إلى LTR محليًا.
- حقل المبلغ يعزل القيمة الرقمية LTR، يحدد `inputmode="decimal"` عند ملاءمته، ويربط العملة بوصف ظاهر أو اسم متاح. الدقة وmin/max والتحقق مسؤولية نموذج المنتج.
- الحقول القصيرة المترابطة يمكن تركيبها في `.dhad-field-pair` بدل فرض stack على كل هاتف؛ يجب أن تبقى صالحة عند 320px والتكبير.
- label من 11–12px، لكنه يجب أن يبقى نصًا حقيقيًا لا placeholder فقط.

### 7.3 البطاقات

- البطاقة العامة المنفذة: radius 14 وpadding 16.
- project card تركيب Pattern: radius 18 وpadding 24، عنوان display، metadata، progress وfooter.
- info card: قابلة للطي، header 13×18، body بحد علوي.
- shot card: radius 14–16، header منفصل، body حقول، done tint أخضر.
- segment card: حاوية لمجموعة shots، header خفيف من accent.
- kanban card: مضغوطة، بيانات قليلة، قائمة أفعال محلية.
- new card: حد متقطع وفعل إنشاء واضح.

### 7.4 الشريط العلوي

- sticky، z-index 300، ارتفاع 52px.
- خلفية شبه شفافة وblur 20px.
- اليمين واليسار يتبعان RTL ودلالات الرجوع/الهوية.
- عنوان المشروع قابل للتحرير دون فتح نموذج منفصل.
- حالة الحفظ والمزامنة تستخدم `.dhad-sync` بنص وشكل معًا و`aria-live`؛ منطق الحفظ نفسه مسؤولية المنتج المضيف.

### 7.5 Progress

```css
width: 100%;
transform: scaleX(var(--dhad-progress));
transform-origin: right;
```

استخدام transform يمنع إعادة التخطيط ويحافظ على اتجاه RTL. يجب وجود عداد نصي مثل `17 / 25` كي لا تكون المعلومة لونية فقط.

### 7.6 Toast

- bottom center.
- neutral/success/warning/error.
- تكديس `column-reverse` كي يظهر الأحدث قرب الأسفل.
- مدة 2.8 ثانية افتراضيًا في الحزمة.
- يتوقف المؤقت عند hover أو انتقال التركيز إلى الإشعار ثم يكمل بعد المغادرة.
- error يأخذ `role="alert"` والبقية `role="status"`.

### 7.7 Dialog / bottom sheet / task form

- يستبدل `alert/confirm/prompt`.
- decision dialog يظهر وسط الشاشة على سطح المكتب ويتحول إلى bottom sheet عند 600px وأقل، بعرض أقصى 480px.
- task-form dialog للإدخال الطويل يبقى inset أو full-height على الهاتف، مع تمرير داخلي ورأس وفعل سفلي ثابتين، ويتجنب لوحة المفاتيح ويحترم safe-area.
- زر الإغلاق في الرأس فعل حقيقي باسم متاح، ولا يغني عن Escape أو فعل الإلغاء عندما يكون القرار مهمًا.
- إغلاق بالـ Escape أو الضغط على الخلفية.
- destructive يلون زر التأكيد بالأحمر.
- يحبس التركيز، يعزل الخلفية، يقفل التمرير، يرتب الطلبات المتزامنة في queue ويعيد التركيز إلى العنصر السابق.

### 7.8 Empty state

- أيقونة دلالية، عنوان، سطران كحد أقصى، ثم فعل واحد أو اثنان.
- لا تعرض empty state إذا كان المحتوى في حالة loading.
- تختلف رسالة «لا توجد بيانات» عن «فشل تحميل البيانات».

### 7.9 Login

- هذا **Guidance only**؛ الحزمة لا توفر عميل مصادقة أو مكوّن Login جاهزًا.
- سطح مستقل في منتصف الشاشة.
- رمز المنتج، عنوان display، وصف قصير، username/password، زر أساسي، رابط التحويل بين الدخول والتسجيل.
- كشف كلمة المرور يملك label واضحًا.
- التحذيرات الأمنية تظهر فقط في سياق التسجيل.

### 7.10 Editors

- rich editor: toolbar كامل عند الحاجة للتنسيق.
- minimal writer: تجربة كتابة نظيفة بحد أقصى 660px.
- يوفر `dhad.patterns.css` هيكل editor/minimal writer فقط. تحويل `#` و`##` وإحصاءات الإنتاج منطق Recipe ينفذه المنتج المضيف.
- المحتوى القابل للتحرير لا يرسم focus ring حول الصفحة كاملة.

### 7.11 Teleprompter

- خلفية سوداء خالصة ونص أبيض.
- 52px، وزن 500، line-height 1.7، تمركز النص.
- padding أفقي 10% + safe areas.
- center line سماوي 3px بشفافية 35%.
- توفر وصفة إنتاج المحتوى الغلاف البصري لهذه الضوابط. mirror وspeed وplay/pause/reset ومزامنة BroadcastChannel منطق منتج غير موجود في runtime العام.

### 7.12 Selection controls

الثلاثة منفذة كأنماط مستقلة حتى عندما تتشارك شكل الحاوية:

- `.dhad-tabs`: `tablist/tab/tabpanel`، roving tabindex، Home/End، وأسهم تتبع اتجاه RTL.
- `.dhad-segmented`: `fieldset` و`legend` مع radio inputs أصلية أو مكافئ يحافظ على الاسم والحالة؛ اختيار واحد فقط.
- `.dhad-view-switcher`: toggle group بـ`aria-pressed` لتغيير projection لنفس البيانات، وليس للتنقل بين صفحات أو تعديل قيمة نموذج.

الحالات: default، hover، selected، focus-visible، disabled، وoverflow. تعتمد selected على توكنات selection المحايدة، لا على success. `.dhad-check` اختيار محايد؛ استخدم modifier completion فقط عندما يعني التحديد اكتمالًا حقيقيًا.

### 7.13 Money and metrics

- `.dhad-money` يرتّب القيمة الأساسية والتحويل والتفصيل، وكل تعبير مالي كامل داخله يعزل LTR ويستعمل `tabular-nums` دون mono.
- القيمة الأصلية هي primary. التحويل الثانوي يأخذ qualifier نصيًا مثل «تقريبًا» أو `≈` مع اسم متاح، ولا يوحي بأنه قيمة محاسبية أصلية.
- `.dhad-money__primary` مضغوط افتراضيًا ليناسب صفوف السجل. أضف `.dhad-amount` صراحة للقيمة البارزة فقط. `.dhad-amount` و`.dhad-metric` أدوار طباعية لا business logic، والمنتج ينسّق العملة والدقة عبر API المنصة.
- حالات unavailable، stale، pending، zero، positive وnegative تحتاج نصًا أو اسمًا متاحًا ولا تعتمد على اللون وحده.

### 7.14 Ledger rows and summaries

- `.dhad-ledger` هو list group يجمع الصفوف على سطح واحد، و`.dhad-ledger__row` يحجز منطقة الوصف والـmetadata ومنطقة القيمة. تظل القيم على محور واحد حتى مع التفاف العربية أو وجود اسم لاتيني.
- `.dhad-summary` يلائم الملخص ذي تسمية وقيمة، و`.dhad-metric-grid` يحافظ على بطاقات المؤشرات المتوازية.
- الصف التفاعلي يستخدم رابطًا أو زرًا حقيقيًا يغطي الهدف المقصود، مع hover/focus/pressed واضح، لا `div` قابل للنقر.

### 7.15 Compact data chart

- `.dhad-mini-chart` يعرض سلسلة زمنية صغيرة ولا يعاد استعمال `.dhad-progress` له.
- ترتيب الزمن يحدده المنتج بوضوح؛ في واجهة RTL يمكن أن يكون الأحدث عند اليمين عندما يخدم القراءة.
- كل عمود يملك قيمة واسمًا متاحين، وتوجد خلاصة نصية للاستنتاج وحالات loading/empty/error. اختلاف الارتفاع أو اللون وحده لا يكفي.

## 8. الحركة

| الحركة | المدة | easing |
|---|---:|---|
| hover/focus | 120–200ms | ease أو expo |
| page change | 220ms | expo |
| progress | 350–400ms | expo |
| sheet in | 300ms | expo |
| toast in | 220ms | expo |
| done ring | 280ms | expo |

كل الحركة تتوقف عمليًا عند `prefers-reduced-motion: reduce`.

## 9. Responsive

الـ breakpoint التنفيذي الأساسي 600px، مع قاعدة إضافية 390px وتوكن مرجعي للأجهزة اللوحية عند 768px.

عند ≤600px:

- padding الصفحة 16px.
- grid البطاقات يصبح عمودًا واحدًا.
- الأزرار الأساسية 44px.
- hover-only actions تصبح ظاهرة.
- topbar أكثر ضغطًا ويحترم safe-area.
- shot header يلتف إلى صفين.
- الحقول الطويلة تنتقل من صف إلى عمود. `.dhad-field-pair` القصير يمكنه البقاء بعمودين حتى يهدد التكبير أو 320px سلامة المحتوى.
- fullscreen ذو عمودين يصبح عمودًا واحدًا.
- decision dialogs تتحول إلى bottom sheets؛ task-form dialogs تستخدم variant مخصصًا ولا تتحول آليًا.
- teleprompter controls تلتف.
- العناصر الثانوية غير المناسبة للموبايل يمكن إخفاؤها، مثل فتح قارئ في نافذة ثانية.

كانبان على الجوال يحتفظ بأعمدة أفقية بعرض يقارب 72vw مع scroll-snap.

## 10. الإيموجي والأيقونات المتكيّفة

لا يفرض النظام مكتبة أيقونات أو قائمة إيموجي ثابتة على كل منتج. القرار يبدأ من طلب المستخدم واللغة البصرية الموجودة في المنتج المضيف:

- إذا طلب المستخدم إيموجي، أو كان المنتج يستخدمها أصلًا، أنشئ قاموسًا صغيرًا خاصًا بمجاله يحافظ على معنى واحد لكل رمز.
- لا تنقل رموز مجال إنتاج الفيديو إلى منتج لا يملك هذه المفاهيم.
- إذا كان المنتج يستعمل أيقونات أصلية أو أيقونات المنصة ولا يستعمل الإيموجي، فعدم إضافة الإيموجي هو القرار الصحيح.
- لا تخلط الإيموجي مع أيقونات outline وfilled ورسومات مخصصة داخل الدور نفسه. يمكن جمع لغتين فقط عندما تكون أدوارهما منفصلة بوضوح، مثل إيموجي داخل المحتوى وأيقونات ثابتة للتحكم.
- الإيموجي الزخرفي يأخذ `aria-hidden="true"`. الإيموجي المعلوماتي المنفرد يحتاج نصًا مكافئًا. زر الإيموجي المنفرد يحتاج `aria-label` صريحًا يصف الفعل لا شكل الرمز.
- تبديل runtime بين `emoji` و`icon` و`none` و`inherit` قابل للعكس، والخريطة الجزئية تترك محتوى المضيف للدور غير المعرّف.
- لا تعتمد على شكل الإيموجي كجزء هندسي دقيق من الهوية، لأن رسمه يختلف بين أنظمة التشغيل.

مثال لمنتج إدارة معرفة، لا كقاموس عام ملزم:

```html
<button class="dhad-icon-btn" type="button" aria-label="حفظ المقالة">
  <span aria-hidden="true">🔖</span>
</button>
<span><span aria-hidden="true">📚</span> مكتبة الفريق</span>
```

قبل التسليم، وثّق: هل استُخدمت الإيموجي؟ ولماذا؟ وما قاموس المعاني الذي اختير لهذا المنتج؟

## 11. الوصول

الموجود في المصدر:

- `lang="ar"` و`dir="rtl"`.
- skip link.
- focus-visible عام.
- labels مخفية بصريًا لحقول الدخول.
- aria-label لعدد كبير من الأزرار الرمزية.
- `role="main"`, `role="banner"`, `role="dialog"` في الأنماط المناسبة.
- minimum 44×44 على الجوال.
- reduced motion.
- حالات نصية بالإضافة إلى اللون.
- safe-area للـ PWA على iOS.

اشتراطات الحزمة عند التوسعة:

- WCAG 2.2 AA كحد أدنى.
- اختبر contrast بعد تركيب alpha colors فوق الخلفية الفعلية.
- لا تجعل drag-and-drop هو الطريق الوحيد؛ وفر menu/أزرارًا بديلة.
- كل icon-only button يحتاج اسمًا متاحًا.
- اختبر tabs وsegmented radio وtoggle group بعقود لوحة المفاتيح الخاصة بكل واحد، ولا تكتفِ بتسلسل Tab بين كل العناصر.
- اختبر المال كجزيرة اتجاه كاملة، وعلاقة المصدر والوجهة كنص مفهوم، والعملات ذات دقات مختلفة.
- runtime يحبس التركيز داخل dialog، يعزل الخلفية، يقفل التمرير، يدعم قائمة انتظار ويعيد التركيز بعد الإغلاق. أعد اختبار هذا العقد داخل إطار المنتج المضيف.
- لا تعتمد على placeholder كـ label.
- اختبر التكبير إلى 200% والعربية ذات الحركات.

## 12. الحوكمة

### تسمية

- CSS classes: `.dhad-*`.
- CSS variables: `--dhad-*`.
- JS global: `Dhad`.
- events: `dhad:*`.
- component modifiers: `--primary`, `--done`.
- state data: `data-state`, `data-done`, `data-dhad-theme`.

### قبول مكوّن جديد

قبل إضافته يجب تحديد:

1. هل هو Core أم Pattern أم Domain recipe؟
2. ما الحالات الكاملة: default/hover/focus/active/disabled/loading/error/success؟
3. كيف يعمل بلوحة المفاتيح والقارئ؟
4. كيف يلتف بالعربية على 320px؟
5. هل يحتاج token جديدًا أم يمكنه استعمال token دلالي قائم؟
6. هل يملك معنى في الوضعين؟
7. هل يحتاج إيموجي أو أيقونة فعلًا؟ وإذا احتاج، هل يطابق لغة المنتج ويملك اسمًا متاحًا؟
8. هل الحالة اختيار أم نجاح أم إجراء؟ لا تستخدم لونًا دلاليًا خاطئًا لمجرد التشابه البصري.
9. هل المكوّن يعرض قيمة منسقة أم ينفذ business logic؟ تبقى الحسابات والسياسات داخل المنتج أو recipe موثقة.

### نوع الأصل ومستوى النضج

- **Implemented** و**Theme starter** و**Guidance only** تصف نوع الأصل المتاح.
- `stable` و`beta` و`experimental` تصف مستوى نضج الأصل المنفذ.
- `recipe` وصفة مجال تحتاج تركيب من المنتج المضيف، وليست مكوّنًا عامًا جاهزًا.

الحالة العامة للأصول المنفذة في هذه الحزمة هي `beta`. لا تصف recipe أو theme starter بأنه مكوّن مكتمل، ولا ترقِ أصلًا إلى `stable` إلا بعد توثيق معايير الحوكمة وجدول حالة المكوّنات في المنتج المضيف.

## 13. ديون التنفيذ التي لا ينبغي نقلها

- CSS وHTML وJavaScript موجودة في ملف واحد ضخم؛ الحزمة فصلتها إلى tokens/components/runtime.
- توجد قيم inline وألوان hardcoded خارج tokens.
- modal styles متكررة بدل primitive واحد.
- شكل الإيموجي يتغير حسب نظام التشغيل؛ لا يُنسخ قاموس منتج بعينه كهوية عامة.
- بعض العبارات 11px؛ لا تصلح للمعلومة الأساسية.
- بعض المكوّنات تعتمد على hover لإظهار أفعالها في سطح المكتب؛ يجب أن تبقى متاحة بلوحة المفاتيح والجوال.
- topbar الأصلي يستعمل `overflow:hidden` وقد يحتاج تدقيقًا مع عناوين طويلة.
- حوارات المصدر المخصصة لا توثق focus trap كاملًا.

يحافظ النظام على هوية ضاد، من دون تثبيت تفاصيل تنفيذ تعيق إعادة الاستخدام.
